الملخص التنفيذي

منصة داخلية لمكتب واحد (أحادية المستأجر)، هدفها ثلاثة أشقّ:

  1. بوابة عميل خفيفة تستقبل طلبات: الاستشارات القانونية (مكتوبة/مرئية)، دراسة القضايا والمستندات، صياغة العقود، أعمال التوثيق، التسجيل العيني للعقار، وخدمات الحوكمة.
  2. نظام إدارة مكتب داخلي متكامل يدير العملاء والقضايا والوكالات والاعتراضات والمستندات والمهل والأتعاب والمصروفات والتقارير.
  3. لوحة تحكم إدارة (Admin) بمدخل مخفٍ لإدارة المستخدمين ومحتوى المنصة والتقارير العامة والإشراف على الطلبات.

المبدأ الحاكم: كل مخرج آلي مسودة مساعدة فقط، لا يصل العميل ولا يُعتمد إلا بمراجعة المحامي عبدالرحمن الهويملي واعتماده.

2

النطاق

داخل النطاق

  • بوابة طلبات العملاء (بلا حساب كامل؛ رابط متابعة + تحقق OTP).
  • وحدات الخدمات: الاستشارات، دراسة القضايا، صياغة العقود، التوثيق، التسجيل العيني، الحوكمة.
  • نظام إدارة المكتب: العملاء، القضايا، الوكالات، الاعتراضات، المستندات، المهل، الأتعاب، المصروفات، التقارير، لوحة التحكم.
  • لوحة تحكم الإدارة (Admin) بمدخل مخفٍ.
  • التكاملات: واتساب المكتب (عبر مزود أعمال معتمد)، زوم، مُيسر (Moyasar) للدفع، Authentica لرموز التحقق.

خارج النطاق (مستبعد صراحةً)

  • مكتبة الأنظمة واللوائح والتعاميم.
  • صياغة مذكرات التقاضي (تحرير دعوى، جوابية، إلحاقية، اعتراض، نقض) وما يتصل بها.
  • الرفع الآلي إلى ناجز/معين.
  • تكامل الفوترة الإلكترونية ZATCA — المكتب غير مسجَّل في ضريبة القيمة المضافة وغير ملزم حالياً.
  • نفاذ (Nafath) — يؤجَّل لمرحلة الوكالات/الرفع الفعلي.
  • لوحة عميل كاملة، وتطبيق الجوال، والواجهة الإنجليزية — مراحل لاحقة.
3

المبادئ العامة الحاكمة

مرجع موحّد تُبنى عليه كل الوحدات:

  1. لا مسار إرسال يتجاوز اعتماد المحامي لأي استشارة أو عقد أو تحليل أو تقرير — ضابط تقني صارم لا سياسة فقط.
  2. عقد أتعاب مكتوب لكل خدمة يحدد النطاق والحدود والمدة وسياسة الإلغاء والاسترداد — لا يكفي «إقرار» في صفحة الدفع.
  3. فحص تعارض المصالح قبل الإسناد وقبل فتح المرفقات للمحامي.
  4. حفظ النص الأصلي للعميل منفصلاً عن أي صياغة مهنية أو إعادة ترتيب.
  5. منع اختلاق المراجع أو الوقائع؛ وسم كل مخرج آلي بوضوح «مسودة غير معتمدة».
  6. نظام حماية البيانات الشخصية (PDPL) كامل التطبيق حتى على النظام الداخلي.
  7. سجل تدقيق غير قابل للتعديل (append-only + تسلسل تجزئة) لكل إجراء ومنفّذه ووقته.
  8. الرسوم الحكومية (توثيق، تسجيل عيني، رفع…) تُعامل كمبالغ مرور لا كإيراد للمكتب، وتُفصل عن أتعاب المكتب.
  9. عدم الاعتماد على اللون وحده لبيان الحالة (اسم نصي دائماً + لون كمؤشر ثانوي)، ومراعاة الوصول لذوي الإعاقة.
  10. خطة بديلة مكتوبة لكل خدمة خارجية (واتساب/زوم/الدفع/رموز التحقق/مزود الذكاء الاصطناعي) عند تعطّلها أو تغيّر واجهتها.

5

بوابة العميل (الواجهة الخارجية)

نموذج الطلب متعدد المراحل

شريط تقدّم واضح، ولا انتقال للمرحلة التالية قبل استكمال الحقول الإلزامية:

  1. نوع الخدمة والمجال القانوني.
  2. بيانات مقدّم الطلب: الاسم، رقم الجوال (يُتحقق بـ OTP عبر Authentica)، صفة العميل، وبيانات الوكيل إن وُجد.
  3. بيانات الطرف الآخر عند الحاجة (لفحص تعارض المصالح).
  4. موضوع الطلب: أسئلة إرشادية متتابعة + التسلسل الزمني + الطلب/النتيجة المرغوبة. يُحفظ نص العميل الأصلي كما هو.
  5. المستندات: رفع ملفات متعددة (PDF/صور/Word)، تصنيف ووصف وتاريخ كل ملف، فحص فيروسات، قائمة نواقص قبل الإرسال.
  6. المراجعة والإقرار: ملخص كامل قابل للتعديل، إقرار بصحة البيانات، الموافقة على سياسة الخصوصية ونطاق الخدمة، وبيان أن قبول الطلب لا يضمن نتيجة.

مساري التسعير

المسارمتىالآلية
سعر ثابت (دفع فوري) استشارة مكتوبة بسيطة (حقوقي/عمالي/أحوال شخصية…)، استشارة مرئية 30 أو 60 دقيقة يظهر السعر مباشرة ← رابط دفع فوري عبر مُيسر

التحقق من السداد (قاعدة المكتب)

بوابة الدفع تؤكد العملية ← الحالة «مدفوع — بانتظار تحقق الموظف» ← الموظف المسؤول يؤكد إتمام السداد ← الحالة «مؤكد — يبدأ العمل وتُحتسب مدة الاستشارة».

متابعة الحالة والإشعارات

  • رابط متابعة خاص بكل طلب + رمز تحقق للجوال.
  • حالات ظاهرة للعميل: بيانات ناقصة، بانتظار الدفع، مدفوع بانتظار التحقق، مؤكد، تحت الإعداد، بانتظار اعتماد المحامي، جاهز، مغلق.
  • إشعارات عبر واتساب/رسالة نصية بقوالب معتمدة، دون أي بيان سري في نص الرسالة.

سياسة الإلغاء وإعادة الجدولة وعدم الحضور

مقترحة — تحتاج إقرار المكتب.
  • إعادة جدولة واحدة مجاناً قبل الموعد بـ 24 ساعة.
  • عدم الحضور دون إشعار: لا استرداد.
  • إلغاء من المكتب: استرداد كامل أو إعادة جدولة باختيار العميل.

سير العمل

استلام الطلب ← فحص تعارض مصالح وبيانات أساسية ← دفع وتحقق الموظف ← (للمرئية) إنشاء اجتماع زوم وإرسال الرابط ← عقد الجلسة/إعداد الرد ← إعادة ترتيب الوقائع وتفريغ الجلسة (ذكاء اصطناعي، مسودة داخلية) ← إعداد المحامي للرد/التقرير واعتماده ← تسليم العميل داخل رابط المتابعة + إشعار ← حفظ نسخة مؤرخة وسجل الاعتماد.

دور الذكاء الاصطناعي هنا

إعادة ترتيب وقائع العميل وصياغة وصف مهني (بلا رأي)، وتفريغ جلسة زوم نصياً. الاثنان مسودة داخلية موسومة «غير معتمدة»، لا تصل العميل إلا بعد اعتماد المحامي.

وحدة دراسة القضايا والمستندات

  • المسار: رفع الملف والمستندات ← عرض سعر ← دفع وتحقق ← دراسة.
  • المخرج: مذكرة دراسة داخلية تشمل: الأطراف، الوقائع، خط زمني، المستندات مصنّفة ومربوطة بالوقائع، نقاط القوة والضعف بصيغة غير جازمة، النواقص المعلوماتية، وتوصية عملية مع تنبيه بضرورة اعتماد المحامي.
  • ذكاء اصطناعي: تلخيص المستندات واستخراج خط زمني — مسودة داخلية.
8

وحدة صياغة العقود

  • أنواع مبدئية: بيع، شراء، شراكة، تخارج، إنشاء تطبيق إلكتروني، وغيرها — القائمة قابلة للتوسعة.
  • لا توجد قوالب جاهزة؛ تُبنى مكتبة قوالب المكتب من الصفر كمشروع فرعي ضمن المرحلة 3.
  • المسار: طلب + مدخلات الأطراف والشروط + مستندات ← عرض سعر (للعقود المعقّدة/الشركات) ← دفع ← مسودة أولية من القالب (ذكاء اصطناعي) ← مراجعة واعتماد المحامي ← تسليم Word/PDF.
  • ذكاء اصطناعي: مسودة أولية من قالب المكتب فقط، لا صياغة حرة بلا قالب، مع استرجاع محكوم ووسم «غير معتمد».
9

وحدة التوثيق

الأعمال: إصدار الوكالات، الإفراغات، الرهون، فك الرهون، الإقرارات المالية.

حقول المعاملة: النوع، الأطراف، المحل (عقار/مبلغ)، رقم المعاملة/الوثيقة، الحالة، الرسوم الحكومية (منفصلة عن أتعاب المكتب)، المستندات، تاريخ الإصدار، الموظف المنفّذ.

بيانات عالية الحساسية ← تشفير + صلاحيات دقيقة + سجل تدقيق. يجب التحقق من متطلبات ترخيص التوثيق وما يسمح النظام بأتمتته قبل الإطلاق.

10

وحدة التسجيل العيني للعقار

المكتب مرخّص بالتسجيل العيني للعقار. المعاملات: البيع، الشراء، الإفراغ، الرهن، فك الرهن، وغيرها مما يتعلق بالعقارات.

حقول المعاملة: رقم الصك/الوثيقة، رقم الهوية العقارية، الموقع، الأطراف، القيمة، الرسوم الحكومية (مرور)، الحالة، المستندات، تاريخ الإجراء، الموظف المنفّذ.

نظام إدارة المكتب (الواجهة الداخلية)

لوحة التحكم

  • عدّاد المراجعين (سجل استقبال يدوي) وعدّاد طلبات الأونلاين.
  • الطلبات بانتظار التحقق من السداد.
  • المهل القريبة (وكالات / اعتراضات / جلسات).
  • المسودات بانتظار اعتماد المحامي.
  • الأتعاب المستحقة غير المدفوعة (مع أسماء العملاء).

العملاء

ملف مستقل لكل عميل: الاسم، الهوية/السجل، الجوال، العنوان، الصفة، مصدر الورود (مراجعة/أونلاين/إحالة)، الملفات المرتبطة (قضايا/استشارات/عقود/توثيق/تسجيل عيني/حوكمة)، وحالة الأتعاب.

القضايا

الحقول: رقم الملف الداخلي، رقم القضية في ناجز، المحكمة/الدائرة، نوع الدعوى، الخصوم، صفة العميل، قيمة المطالبة، المحامي المسؤول، الحالة، تاريخ القيد، درجة التقاضي الحالية، الجلسات، الأحكام/القرارات الصادرة، المهل الحرجة، المستندات، الأتعاب المتفق عليها/المدفوعة/المتبقية، الوكالة المرتبطة، الاعتراضات المرتبطة، الاستشارة الأصلية (إن تحوّلت لقضية)، ملاحظات داخلية مخفية.

الحالات (قائمة قابلة للتهيئة من المدير): قيد الدراسة، لم تُقيَّد بعد، مقيّدة، مرافعة، صلح، تحقيق، حجز للحكم، صدر الحكم، اعتراض/استئناف، محكمة عليا، تنفيذ، منتهية، محفوظة/مغلقة، معلّقة. لكل حالة اسم نصي + لون (اللون مؤشر ثانوي). القضية المنتهية تظهر بعلامة «منتهية»، والتي في الصلح بعلامة «صلح»، وهكذا.

الوكالات

رقم الوكالة، الموكِّل، النطاق، تاريخ الإصدار، تاريخ الانتهاء، المدة المتبقية (تُحسب تلقائياً)، القضايا المغطاة، المستندات.

  • إدخال يدوي من الموظف — لا يوجد ربط رسمي متاح مع نظام الوكالات الإلكترونية للجهات الخاصة.
  • الفرز الافتراضي بالأقرب انتهاءً + فلترة (بالعميل/الحالة/الفترة) + تذكير تلقائي قبل الانتهاء بمدة يحددها المكتب.

الاعتراضات

رقم الصك/الحكم، تاريخ التبليغ أو العلم (إدخال)، مهلة الاعتراض المحسوبة — تُعرض كتقدير بعلامة «يتطلب تحقق المحامي» لا كموعد نهائي قاطع — الحالة، القضية المرتبطة، المستندات. فرز بالأقرب انتهاءً + فلترة.

التوثيق / التسجيل العيني / الحوكمة

عرض ملفات كل وحدة بحقولها (المذكورة في البنود 9–11)، ضمن نفس نمط الأيقونات والفلترة.

المستندات

مستودع مركزي، تصنيف ووصف، ربط بالملف/الواقعة، إصدارات، فحص فيروسات، أنواع مسموحة، استخراج نص عند الحاجة (OCR للممسوح ضوئياً — دقة متوسطة للعربية).

محرك المهل والمواعيد (موحّد)

يجمع: الوكالات + الاعتراضات + الجلسات + مهل عروض الأسعار + مواعيد تسليم التقارير. عرض موحّد + تنبيهات + ثلاث واجهات متخصصة (وكالات/اعتراضات/جلسات).

لوحة تحكم الإدارة (Admin) — مدخل مخفٍ

الطبيعة والوصول

  • كونسول منفصل عن واجهة إدارة المكتب التشغيلية، على مدخل مخفٍ (نطاق فرعي/مسار غير مُعلن، غير مرتبط بأي رابط من المنصة العامة، ومستبعَد من فهرسة محركات البحث عبر robots وترويسات noindex).
  • تسجيل دخول مستقل باسم مستخدم وكلمة مرور + مصادقة متعددة العوامل إلزامية (OTP عبر Authentica)، مع تحديد معدل المحاولات وقفل مؤقت بعد محاولات فاشلة، وتسجيل كل محاولة دخول في سجل التدقيق.
  • الدور: مسؤول المنصة (Admin)، يحمله المحامي عبدالرحمن مبدئياً، ومفصول صلاحياً عن دور «موظف».

الصفحات

  1. تقارير عامة مع فرز بالتاريخ (من/إلى): الإيرادات (المدفوعات المكتملة عبر مُيسر) بحسب الخدمة والفترة؛ الطلبات الواردة الجديدة بحسب المصدر (أونلاين/مراجعة/إحالة) والفترة؛ تغييرات كتالوج الخدمات/الباقات (ما أُضيف/عُدِّل/أُوقف)؛ تصدير PDF/Excel.
  2. إدارة المستخدمين: تصفّح ملفات المستخدمين (حسابات الموظفين + سجلات جهات اتصال العملاء)، تعديل البيانات، تفعيل/تعطيل حساب، إعادة تعيين كلمة المرور، إدارة الأدوار والصلاحيات. كل تعديل يُسجَّل في سجل التدقيق مع المنفِّذ والوقت.
  3. إدارة الطلبات: قائمة بآخر الطلبات وحالاتها، فرز بالحالة وبالتاريخ، فتح تفاصيل الطلب، تتبّع مسار الدفع والاعتماد. (إشراف واطلاع؛ الاعتماد المهني يبقى بيد المحامي.)
  4. التحكم في محتوى المنصة: صورة البانر في الصفحة الرئيسية، الأقسام/المسارات المعروضة وترتيبها، النصوص التعريفية لكل خدمة، الأسعار المعروضة للباقات الثابتة، والأسئلة الشائعة. تغييرات المحتوى تمرّ بمعاينة قبل النشر وتُحفظ بإصدارات.

ملاحظة على المصطلحات

مصطلحات «المبيعات / التسجيلات / السلع» مأخوذة من نموذج متجر إلكتروني عام. في سياق مكتب المحاماة تُقرأ: الإيرادات من الخدمات، الطلبات الواردة، وكتالوج الخدمات/الباقات — لا يوجد كتالوج «سلع» بالمعنى التجاري.

التكاملات

واتساب المكتب

مزود أعمال معتمد (BSP)، قوالب رسائل مُوافَق عليها مسبقاً، موافقة العميل (opt-in)، ومنع أي بيان سري في نص الرسالة (البيانات تمر عبر Meta).

الاستخدامات: تأكيد الطلب، طلب المستندات الناقصة، رابط الدفع، تأكيد الموعد ورابط زوم، تحديثات الحالة، التذكيرات.

زوم

إنشاء الاجتماع تلقائياً بعد الدفع وتأكيد الموعد من حساب المكتب، إرسال الرابط للعميل والمحامي، تذكير قبل الموعد، تتبّع حالات الموعد (محجوز/مؤكد/بدأ/انتهى/أُعيدت جدولته/أُلغي). التسجيل معطّل افتراضياً؛ إن استُخدم فبموافقة صريحة من الطرفين وسياسة حفظ محددة.

مزود الدفع — مُيسر (Moyasar)

  • بوابة الدفع المعتمدة: مُيسر، تدعم مدى، البطاقات الائتمانية، Apple Pay، STC Pay.
  • يُستخدَم skill الربط من مستودع khaled-harthi/saudi-skills عند التنفيذ (/plugin install moyasar).
  • استقبال تأكيد الدفع عبر webhook، مفتاح idempotency، منع تكرار الخصم، مسار استرداد واضح.
  • لا تُخزَّن بيانات البطاقات في المنصة (تبقى لدى مُيسر بصفته الملتزم بمعيار PCI-DSS).

رموز التحقق — Authentica

  • إرسال رمز التحقق للجوال (OTP عبر SMS) عبر Authentica: تحقق جوال العميل عند تقديم الطلب ومتابعة الحالة، ومصادقة ثنائية (2FA) لحسابات المكتب ولوحة الإدارة.
  • يُستخدَم skill الربط من نفس المستودع (/plugin install authentica-otp).
  • انتهاء صلاحية الرمز، حدّ لمحاولات الإدخال، وتحديد معدل الإرسال لكل رقم.

الفاتورة

فاتورة/إيصال إلكتروني بسيط بلا بند ضريبة، مربوط برقم الطلب وملف العميل، ومنع تكرار الإصدار عند إعادة التحميل.

الأمن والخصوصية والامتثال

كلمات المرور والحسابات

  • تُخزَّن جميع كلمات مرور الحسابات (الإدارة والموظفين) بخوارزمية تجزئة مخصّصة لكلمات المرور (bcrypt أو Argon2id) بملح فريد لكل مستخدم — لا تشفير قابل للعكس ولا تخزين نصّي.
  • سياسة قوة كلمة مرور، قفل بعد محاولات فاشلة، تحديد معدل تسجيل الدخول، ومصادقة متعددة العوامل لحسابات الإدارة والمكتب.

الصور والملفات المرفوعة

  • عند رفع صور الواجهة (البانر، الصور الرمزية، الصور التعريفية): ضغط وتصغير من جهة الخادم دون إضرار بالجودة الظاهرة — تحجيم لأبعاد قصوى معقولة، توليد أحجام متجاوبة (مصغّرة/عرض/أصلية)، تحويل إلى صيغة حديثة (WebP/AVIF) مع بديل، إزالة بيانات EXIF (بينها الموقع الجغرافي) للخصوصية، وتحميل مؤجَّل (lazy-load) في الواجهة.
  • استثناء: مسوحات المستندات والأدلة القانونية لا تُضغط ضغطاً فاقداً؛ تُحفظ بدقتها الأصلية (الضغط للصور التسويقية/الواجهة فقط).
  • فحص فيروسات لكل ملف، أنواع مسموحة محدّدة، حدّ لحجم الملف.

الامتثال النظامي

  • PDPL: أساس نظامي لكل معالجة، سجل أنشطة المعالجة، تقييم أثر لحماية البيانات، إجراء إشعار تسرب خلال 72 ساعة، آلية تنفيذ حقوق صاحب البيانات (وصول/تصحيح/حذف)، ضوابط النقل خارج المملكة. بيانات الهوية والصكوك والإقرارات المالية = بيانات حساسة.
  • نظام المحاماة ولائحته وقواعد الهيئة السعودية للمحامين: لا ممارسة بلا ترخيص (لا رأي آلي يصل العميل)، سرية المهنة، ومراجعة قواعد الإعلان الإلكتروني قبل الإطلاق (لا ضمان نتيجة، لا مقارنات مضللة).
  • التوقيع الإلكتروني: تمييز الإقرار البسيط عن التوقيع الرقمي المعتمد؛ ختم زمني لاعتمادات المحامي وإقرارات العميل.

البنية والتشغيل

  • الاستضافة داخل المملكة، مع تطبيق ضوابط الهيئة الوطنية للأمن السيبراني (ECC) وتصنيف البيانات والإطار التنظيمي للحوسبة السحابية.
  • تشفير أثناء النقل والتخزين، صلاحيات دقيقة، عزل ملفات كل عميل.
  • اتفاقية معالجة بيانات مع مزود الذكاء الاصطناعي تنص على عدم الاحتفاظ وعدم التدريب وتحديد موقع المعالجة، وإدراجه كمعالِج ثانوي في سجل PDPL. منع استخدام بيانات العملاء لتدريب أي نموذج.
  • نسخ احتياطية وخطة استعادة مُختبرة دورياً بأهداف RTO/RPO، وسياسة احتفاظ وحذف مرتبطة بمدد التقادم والالتزامات المهنية.
  • سجل تدقيق append-only + تسلسل تجزئة.
  • تحديد المعدل ومكافحة الإساءة على البوابة العامة، وسياسة الطلبات الوهمية واستهلاك الموارد قبل الدفع.
  • SPF/DKIM/DMARC ومزود بريد معاملاتي.

ضوابط الذكاء الاصطناعي

  • استرجاع محكوم (RAG) من قوالب المكتب والمستندات المرفوعة فقط، مع إظهار الاستشهاد ورفض الإجابة عند غياب المصدر.
  • عزل محتوى المستندات المرفوعة كبيانات لا كأوامر (حماية من حقن الأوامر عبر ملفات العملاء).
  • وسم كل مخرج «مسودة غير معتمدة».
  • منظومة تقييم دورية (هلوسة، اقتباس خاطئ) قبل كل إطلاق.
  • الاستخدامات المفعّلة (الأربعة): (1) إعادة ترتيب وقائع العميل وصياغة وصف مهني بلا رأي، (2) تلخيص مستندات القضية واستخراج خط زمني، (3) تفريغ جلسات زوم نصياً، (4) مسودة أولية للعقد من قوالب المكتب. جميعها مخرجات داخلية خلف اعتماد المحامي.
17

سير العمل الآلي (من الطلب إلى الإغلاق)

  1. استلام الطلب ← رقم طلب + ملف مبدئي.
  2. فحص آلي للحقول والمستندات الإلزامية + قائمة نواقص.
  3. فحص تعارض المصالح.
  4. تحديد المسار (سعر ثابت / عرض سعر).
  5. الدفع عبر مُيسر ← تحقق الموظف من إتمام السداد.
  6. إنشاء ملف الخدمة/القضية + قائمة مهام.
  7. تجهيز ملخص/خط زمني/مسودة (ذكاء اصطناعي، غير معتمد).
  8. مراجعة واعتماد المحامي.
  9. تسليم العميل (تقرير/عقد/استشارة) داخل رابط المتابعة + إشعار — مع منع إرسال أي معلومة غير معتمدة.
  10. تحديث الأتعاب، إنشاء تذكيرات المهل، الأرشفة، وحفظ سجل التدقيق.
18

النموذج التقني المقترح

  • تطبيق ويب متجاوب (عربي RTL؛ الإنجليزية مرحلة لاحقة)، بثلاث واجهات منفصلة: بوابة العميل، نظام المكتب الداخلي، لوحة الإدارة المخفية.
  • الواجهات مبنية على Base UI (مكوّنات React غير المنسّقة) مع تخصيص كامل بهوية المنصة (نظام الألوان والخطوط العربية المعتمد)، وحالات تركيز ظاهرة، ودعم قارئ الشاشة، ودعم RTL.
  • قاعدة بيانات علائقية واحدة + مستودع مستندات + طبقة تكاملات (واتساب/زوم/مُيسر/Authentica).
  • مُيسر (Moyasar) للمدفوعات وAuthentica لرموز التحقق، عبر skills مستودع khaled-harthi/saudi-skills (/plugin marketplace add khaled-harthi/saudi-skills ثم /plugin install moyasar و/plugin install authentica-otp).
  • طبقة ذكاء اصطناعي عبر مزود ملتزم باتفاقية معالجة (بلا احتفاظ/تدريب).
  • بيئات منفصلة (تطوير/اختبار/إنتاج)، نسخ احتياطية، مراقبة وتنبيهات.
  • استضافة داخل المملكة.

مخطط البيانات المبدئي (الكيانات)

عميل، جهة اتصال، طلب، خدمة/باقة، استشارة، قضية، جلسة، وكالة، اعتراض، معاملة توثيق، معاملة تسجيل عيني، مشروع حوكمة، مستند، عرض سعر، دفعة، فاتورة، مصروف، مهمة، تذكير، مستخدم، دور/صلاحية، محتوى صفحة (بانر/قسم)، سجل تدقيق.

علاقات أساسية: العميل ← له عدة ملفات (قضايا/استشارات/…)؛ الطلب ← يُنشئ خدمة/قضية؛ القضية ← ترتبط بوكالة واحدة أو أكثر واعتراضات وجلسات ومستندات ودفعات؛ كل إجراء ← يُسجَّل في سجل التدقيق.
